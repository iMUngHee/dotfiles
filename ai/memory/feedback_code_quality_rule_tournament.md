`ai/rules/code-quality.md` is the winner of a pre-registered tournament, not a hand-picked draft. Reword it only after re-running the comparison.

**Why:** 대협 asked that the rule be chosen from candidates rather than written once. Two tournaments decided the current text.

- 2026-11-10, executor Opus 5.5. Five wordings were ranked by Claude and Codex (Borda) into three finalists: C1 principle sentences, C4 the same with Bad/Good examples, C5 an end-of-work checklist. Each finalist and a no-rule baseline ran three slop-inducing tasks (Go, TypeScript, Python) twice through `claude -p --setting-sources project` (user config isolated and verified by a sentinel probe). Every run passed its hidden tests. Scores: baseline 0.399, C1 0.443, C5 0.442, C4 0.457. Only C4 cleared the fixed bar of baseline + 0.05, so it was adopted despite costing the most always-on bytes.
- 2026-11-17, executor Claude Fable 5.2 at effort medium. The harness had not been kept, so the tasks, hidden tests and scoring were rebuilt from this note and pre-registered again. Conditions: no rule, C4 verbatim, and C1r (C4 with every Bad/Good line removed, 1280 bytes against 1860). All 18 runs passed their hidden tests. Scores: baseline 0.645, C4 0.856, C1r 0.867. Both wordings cleared baseline + 0.05, and C1r scored 0.011 above C4, inside the 0.03 near-tie band, so the shorter wording won and 대협 adopted it the same day.

**Limits:** six runs per condition in both tournaments, and one executor model and effort level each. The two tournaments used different tasks and a rebuilt formula, so their numbers are not comparable with each other. C1r is a reconstruction: the original C1 and C5 texts were not kept, and C5 was not re-run. Internal-artifact comments never appeared in any run of either tournament, the baselines included, so the comment line is still unmeasured. In 2026-11-10 every candidate scored below the baseline in Python; in 2026-11-17 Python showed the largest gain (93% of the new code went into the crowded main file without a rule, 23-40% with one).

**How to apply:** Before rewording, shortening or extending the rule, re-run the comparison. Keep a new wording only if it clears baseline + 0.05 and either beats the current text or is shorter and within 0.03 of it. The harness lived in `/tmp` and is gone, so rebuild it: three tasks in different languages, each with a step-numbered work order, a crowded main file, external input, an existing helper and an input-size hint, plus hidden tests; each wording and a no-rule baseline run twice per task in a fresh repo through `claude -p --setting-sources project --append-system-prompt`; a run that fails its hidden tests scores 0; score = half blind judging (Claude and Codex, 1-5 on modules, types, comments, performance, placement) and half artifact-comment, type-escape and main-file-share counts normalized to the baseline. The 18 Fable 5.2 runs cost about $18 of usage, and starting 15 of them at once exhausted the account's 5-hour limit; run four at a time. Enforcement does not rest on the rule alone: the `tidy` skill cleans a diff, and on Claude pre-commit-verifier Check 8 flags artifact comments; Codex has the rule and `tidy` but no commit-time check.
